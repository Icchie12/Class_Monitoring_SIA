# Online Class Monitor — Google Meet prototype

This version uses the **Google Meet REST API** to automatically detect participants in the teacher's active meeting, while the Chrome extension handles browser activity such as tab changes and student activity signals.

## Important

This is a school prototype. Google Meet participant monitoring requires the teacher to authorize the app with a Google account. The project uses the `meetings.space.readonly` OAuth scope.

### 1. Install packages

PowerShell:

```powershell
.\venv\Scripts\python.exe -m pip install -r requirements.txt
```

### 2. Create Google OAuth credentials

In Google Cloud Console:

1. Create/select a project.
2. Enable the **Google Meet REST API**.
3. Configure the OAuth consent screen.
4. Create an **OAuth Client ID** for a **Desktop app**.
5. Download the client JSON.
6. Rename it to `credentials.json`.
7. Put it beside `app.py`.

For local testing, the Google account used to authorize the app must be permitted by the OAuth consent-screen/testing configuration.

### 3. Run

```powershell
.\venv\Scripts\python.exe app.py
```

Open:

`http://127.0.0.1:5000/`

### 4. Teacher flow

1. Click **Connect Google Account**.
2. Sign in with the teacher's Google account.
3. Grant Meet read access.
4. Enter class name, teacher email, and the exact Google Meet URL.
5. Click **Start Monitoring**.
6. The dashboard polls the Meet API every 5 seconds.
7. Students currently in the active conference appear automatically.
8. When a participant is no longer in the active participant list, the prototype marks them `LEFT` and records a time out.

### 5. Student browser monitoring

On each student's computer:

1. Load the `extension` folder at `chrome://extensions` with Developer mode enabled.
2. Open `http://127.0.0.1:5000/student`.
3. Enter the session ID and the student's name.
4. Click **Start Monitoring**.
5. Open the class's Google Meet in the same Chrome profile.

The extension then sends browser activity and tab-change events to the backend.

## What comes from where?

- **Student appears in the dashboard:** Google Meet REST API.
- **Time in:** Meet participant record.
- **Time out:** disappearance from active participant sessions / Meet record.
- **Tab changes:** Chrome extension.
- **Last activity:** Chrome extension heartbeat/activity events.
- **Camera/mic:** best-effort Meet UI detection by extension; not an authoritative Meet API field in this prototype.
- **Excel:** generated by Flask/openpyxl.
- **Email:** optional SMTP configuration.

Do not treat the browser extension's camera/mic detection as a guaranteed production-grade signal because Google Meet's internal page structure can change.


## v4 fixes
- Browser tab switching is tracked by both Chrome tab activation and Meet page visibility/focus.
- Extension receives the backend URL from the student setup page, avoiding hardcoded localhost when students use another device.
- Excel report timestamps are converted to Asia/Manila and include the explicit +08:00 offset.
- Gmail sending requires re-authorizing the Google account after the gmail.send scope is added.
